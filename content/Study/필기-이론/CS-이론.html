CS 이론

Jan 06, 202643 min read

  • CS

객체 지향 프로그래밍 (OOP)

상속 (Inheritance)

  • 기존 클래스의 속성과 Method를 물려받는 것

장점

  • 코드 재사용
  • 계층적 분류
  • 확장성

주의사항

  • ❌ 너무 깊은 상속 계층 (3-4단계 이상)
  • ❌ 다중 상속 (C++에서는 가능하지만 복잡)

예시

다형성 (Polymorphism)

  • 같은 Interface를 통해서 다른 동작을 수행
  • 게임 활용:
    • 다양한 Enemy 타입 (Zombie, Skeleton, Boss)
    • 다양항 Weapon 타입 (Gun, Sword, Bow)
    • AI 상태 패턴

Compile Time 다형성 (Overloading)

Runtime 다형성 (Overriding + Virtual Function)

캡슐화 (Encapsulation)

  • 데이터와 Method를 하나로 묶고, 외부 접근을 단계별로 제한
  • 장점
    • 데이터 무결성 보장
    • 유지보수 용이
    • 코드 수정 시 영향 범위 최소화

접근 지정자

  • {C++}public : 어디서나 접근 가능
  • {C++}protected : 상속받은 클래스에서만 접근 가능
  • {C++}private : 클래스 내부에서만 접근 가능

예시

추상화 (Abstraction)

  • 복잡한 시스템을 단순한 인터페이스로 표현
  • 게임 활용
    • 렌더링 시스템
    • AI 시스템
    • 물리 시스템 등 시스템 구현
  • Java같은 경우 Interface와 Abstract Class를 구분해서 만들지만 C++는 구현에 구분은 없고 클래스에 하나 이상의 Pure Virtual Function이 있다면 Abstract Class라고 부를 수 있고 만약 클래스의 모든 함수가 전부 Pure Virtual Function으로만 구성되어 있어서 구현이 없다면 Interface라고 부름
  • 추상 클래스나 인터페이스 클래스 자체로는 Instance를 생성할 수 없음음

Abstract Class(추상 클래스) / Interface (인터페이스)

가상 함수 (Virtual Function)

  • 가상 함수는 같은 함수 선언이지만 각각의 자식 클래스에서 세부 구현이 달라서 다르게 동작하는 함수들이고 다르게 동작하기 위해서 virtual table이 사용됨

vtable (가상 함수 테이블) 동작 원리

  • 가상 함수를 가진 Class는 vtable(virtual table)을 가짐
  • 구조
      1. 각 클래스는 하나의 vtable 보유
      1. vtable은 가상 함수 포인터들의 배열
      1. 객체는 vtable을 가리키는 vptr(virtual pointer) 보유
  • 비용
    • 메모리: 객체당 vptr 1개 (보통 8바이트)
    • 성능: 간접 호출 (1-2 사이클 느림)
  • 언제 사용
    • ✅ 다형성이 필요할 때
    • ❌ 성능이 매우 중요한 루프
  • 생성자에서 가상 함수를 호출 붕가능
    • 생성 중에는 아직 자식 클래스의 vptr이 설정되지 않았거나 부모 클래스의 vptr을 가르키고 있으므로 자식이 override한 함수가 아닌 부모의 함수가 호출됨

예시

메모리 구조

Base 객체:
[vptr] → Base vtable
         [&Base::Foo]
         [&Base::Bar]

Derived 객체:
[vptr] → Derived vtable
         [&Derived::Foo]  // 오버라이드
         [&Base::Bar]     // 그대로 사용

함수 호출 과정

    1. ptr이 가리키는 객체의 vptr 읽기
    1. vptr을 통해 vtable 접근
    1. vtable에서 Foo() 함수 포인터 가져오기
    1. 해당 함수 호출 → Derived::Foo()

순수 가상 함수 (Pure Virtual Function)

  • 구현이 없는 가상 함수로 선언 맨 마지막에 {C++}= 0를 붙여서 선언해줌
  • 특징
    • Abstract Class가 됨 (Instance 생성 불가)
    • Inheritance Class에서 반드시 구현해줘야 함
  • 게임 활용
    • 컴포넌트 시스템
    • 플러그인 아키텍처
    • 인터페이스 정의

예시

가상 소멸자의 중요성

  • 다형성을 사용할 때 소멸자를 virtual로 선언해줘야 함
    • 다형성을 사용하는 경우 부모 클래스의 포인터에서 자식 클래스의 Instance를 생성하는 경우가 있는데 virtual dectructor로 만들지 않는다면 해당 객체가 소멸될때 자식 클래스의 소멸자는 실행되지 않고 해당 부모 포인터의 소멸자만 실행되기 때문에 만약 자식 클래스에서 raw pointer로 동적 할당한 뒤 소멸자에서 해제하는 흐름이라면 할당된 메모리를 해제하지 않아서 Memory Leak이 발생
    • 가상 소멸자를 사용해야지 자식 클래스의 소멸자도 제대로 호출되기 때문에 이런 상황을 방지할 수 있음음
  • 규칙
    • ✅ 가상 함수가 하나라도 있으면 소멸자도 virtual로
    • ✅ 다형성을 사용하는 베이스 클래스는 항상 virtual destructor

Stack vs Heap 메모리

  • 게임에서 활용
    • Stack: 지역 변수, 함수 매개변수
    • Heap: 동적 객체 (Enemy, Bullet 등)

Stack

  • 자동 관리 (Scope를 벗어나면 자동 해제)
  • 빠름
  • 크기 제한 (보통 1~8MB)
  • LIFO (Last In First Out)
예시

Heap

  • 수동 관리 (new/delete) - 동적 할당
  • 느림
  • 크기 제한 거의 없음
  • 단편화 발생 가능
예시

new/delete vs malloc/free

  • 규칙
    • ✅ C++에서는 new/delete 사용
    • ❌ new와 free 혼용 금지
    • ❌ malloc과 delete 혼용 금지

new/delete

  • C++ style
  • 생성자/소멸자 호출
  • Type 안전
  • 연산자 오버로딩 가능

malloc/free

  • C style
  • 생성자/소멸자 호출 안함
  • void* 반환 (Casting 필요)
  • Byte 단위 할당

Smart Pointer

  • 자동으로 메모리를 관리하는 포인터
  • 게임 활용:
    • ✅ unique_ptr: 독립적인 객체 (Player, Camera)
    • ✅ shared_ptr: 공유 리소스 (Texture, Mesh)
    • ✅ weak_ptr: 관찰자 패턴, 부모-자식 관계

unique_ptr

  • 독점 소유권
  • 특징
    • 복사 불가, 이동만 가능
    • Overhead 거의 없음

shared_ptr

  • 공유 소유권
    • 내부적으로 Reference Counting
  • 특징
    • 복사 가능
    • 참조 카운트 관리 (약간의 Overhead 발생)

weak_ptr

  • 약한 참조 (순환 참조 방지)
순환 참조 문제
해결 방법

RAII (Resource Acquisition Is Initialization)

  • 자원을 관리하는 패턴으로 Resource의 획득은 생성자에서 해제는 소멸자에서 선언해서 객체가 생성되고 해제될때 자동으로 자원을 관리하도록 하는 것
  • 원칙
    • 객체 생성 시 리소스 획득
    • 객체 소멸 시 리소스 해제
    • Scope 기반 관리
  • 장점
    • ✅ 예외 안전성 (exception safety)
    • ✅ 자동 정리
    • ✅ 메모리 누수 방지
  • 게임 활용
    • ✅ 파일 핸들
    • ✅ GPU 리소스 (텍스처, 버퍼)
    • ✅ 뮤텍스 락

메모리 누수 방지

  • 메모리 Leak의 주요 원인
    • new 후 delete을 하지 않는 경우
    • 예외 발생 시 delete 도달 못함
    • 순환 참조

Chaining

  • 각 버킷이 연결 리스트(Linked List)를 가짐
  • 충돌 시 리스트에 추가
  • 장점: 삭제가 쉽고 테이블이 꽉 차지 않음
  • 단점: 포인터 오버헤드, 캐시 효율 나쁨

Open Addressing

  • 충돌 시 다른 빈 버킷을 찾음 (Linear Probing: +1, +2…)
  • 장점: 메모리 할당 없음, 캐시 효율 좋음
  • 단점: 클러스터링(데이터 뭉침) 발생 시 성능 급하락
  • 펄어비스 등 고성능 엔진에서는 캐시 효율 때문에 Open Addressing 선호 경향

메모리 관리 및 최적화 (Memory & Optimization)

메모리 풀 (Memory Pool)

  • 작은 객체를 빈번하게 new/delete하면 힙 단편화(Fragmentation)와 오버헤드 발생
  • 미리 큰 메모리 블록(Chunk)을 할당해두고, 이를 잘라서 씀
  • 해제 시 운영체제에 반환하지 않고 풀에 돌려놓음
  • 장점
      1. 할당/해제 속도가 매우 빠름 (단순 포인터 연산)
      1. 캐시 지역성(Locality) 향상 (메모리가 연속적일 확률 높음)
      1. 단편화 방지

캐시 일관성 (Cache Coherency) & False Sharing

  • 문제 상황 - False Sharing
    • 서로 다른 변수 a, b가 같은 캐시 라인(64 byte)에 존재
    • Core 1이 a를 수정하면, Core 2의 캐시에 있는 b(같은 라인)도 무효화(Invalidate)됨
    • Core 2가 b를 읽을 때 강제로 메모리에서 다시 읽어야 함 → 성능 저하
  • Padding으로 해결

STL (Standard Template Library)

자료구조

  • 게임 활용
    • vector: 동적 배열, Enemy 리스트
    • map: 이름으로 찾기 (ItemName → ItemData)
    • unordered_map: 빠른 검색 (EntityID → Entity)
    • set: 유일한 값 관리 (ActivePlayers)
    • queue: BFS, 이벤트 큐
    • stack: DFS, Undo 시스템
    • priority_queue: A* 알고리즘, 이벤트 스케줄러

vector

  • 동적 배열
  • 시간 복잡도:
    • 접근: O(1)
    • 끝 추가/삭제: O(1) 평균
    • 중간 삽입/삭제: O(n)
  • vector의 재할당 (Reallocation)
      1. push_back 시 capacity가 꽉 참
      1. 새로운 메모리 할당 (기존 capacity의 1.5배 또는 2배)
      1. 기존 원소들을 이동(Move) 또는 복사(Copy) (C++11 이상은 Move 시도)
      1. 기존 메모리 해제
      1. 새 원소 추가
    • 최적화
      • {C++}vector::reserve(n)을 사용하여 재할당을 방지하는 것이 핵심

map

  • key-value 쌍 (Red-Black Tree)
  • key값을 기반으로 정렬되며 저장
  • 시간 복잡도:
    • 삽입/삭제/검색: O(log n)

unordered_map

  • key-value 쌍 (Hash Table)
  • 정렬되지 않고 저장
  • 시간 복잡도:
    • 삽입/삭제/검색: O(1) 평균

set

  • 중복 없는 집합 (Red-Black Tree)
  • 정렬되며 저장
  • 시간 복잡도:
    • 삽입/삭제/검색: O(log n)

queue

  • FIFO

stack

  • LIFO

priority_queue

  • 우선순위 큐 (Heap)

iterator 사용법

  • 반복자
    • Container의 요소를 순회

시간 복잡도

  • 선택 기준
    • 빠른 접근 필요: vector, array
    • 빈번한 삽입/삭제: list
    • 정렬된 순서 + 검색: map, set
    • 빠른 검색만: unordered_map, unordered_set
    • 우선순위 필요: priority_queue

vector

  • 접근: O(1)
  • 끝 추가: O(1) 평균, O(n) 최악 (재할당)
  • 끝 삭제: O(1)
  • 중간 삽입/삭제: O(n)

list (이중 연결 리스트):

  • 접근: O(n)
  • 앞/뒤 추가/삭제: O(1)
  • 중간 삽입/삭제: O(1) (iterator 위치 알 때)

map/set (Red-Black Tree):

  • 삽입/삭제/검색: O(log n)
  • 정렬된 순서 유지

unordered_map/unordered_set (Hash Table):

  • 삽입/삭제/검색: O(1) 평균, O(n) 최악
  • 순서 보장 안 함

priority_queue (Heap):

  • 삽입: O(log n)
  • 최대/최소 접근: O(1)
  • 삭제: O(log n)

C++ 심화

Overloading vs Overriding

Overloading

  • 같은 이름, 다른 매개변수
  • Compile 타임에 결정됨

Overriding

  • 상속 + virtual function
  • Runtime에 결정

const와 constexpr

const

  • Runtime 상수로 Runtime이나 Compile Time에 어떤값으로 선언될지 결정될 수 있음

constexpr

  • compile time 상수로 어떤 값일지 미리 지정되어야 함

casting (변환)

static_cast

  • 일반적인 Type 변환

dynamic_cast

  • 안전한 Down Casting으로 변환할 수 없다면 nullptr을 반환해줌
  • RAII 패턴을 사용해야 안전한 Resource 관리가 가능

const_cast

  • const 제거 및 추가하는 casting으로 위험함

reinterpret_cast

  • Bit 단위로 재해석하는 것으로 무조건 Casting을 하기 때문에 매우 위험함

Reference vs Pointer

  • 게임 활용
    • Reference: 함수 인자 (복사 방지)
    • Pointer: 동적 객체, nullptr 필요한 경우

Reference

  • {C++}&로 선언
  • 별칭 (Alias)
  • 초기화 필수
  • nullptr 불가
  • 재할당 불가

Pointer

  • {C++}*로 선언
  • 주소 저장
  • nullptr 가능
  • 재할당 가능

Copy Constructor vs Move Constructor

  • 게임 활용
    • Copy: 진짜 복사 필요할 때
    • Move: 임시 객체, 리소스 이전

Copy Constructor

  • 복사 생성자

Move Constructor

  • 이동 생성자

Lambda Function

  • 익명 함수로 해당 Scope에서 임시로 선언해 사용할때 사용
  • 문법
    • [capture](parameters) -> return_type { body }
  • 게임 활용
    • ✅ 이벤트 콜백
    • ✅ 정렬 비교 함수
    • ✅ 짧은 유틸리티 함수

RVO (Return Value Optimization)

  • 원리
    • 함수가 객체를 반환할 때, 임시 객체의 생성/복사/파괴 비용을 없애는 컴파일러 최적화.

운영체제

Process vs Thread

Process

  • 독립적인 메모리 공간
  • 프로그램 실행 단위
  • 무거움 (생성/전환 비용 큼)
  • 여러 Process를 사용해 병렬처리가 가능하지만 복잡하고 어려움

Thread

  • 프로세스 내부의 실행 흐름
  • 메모리 공간 공유
  • 가벼움
  • 게임 활용
    • ✅ 렌더링 스레드 / 로직 스레드 분리
    • ✅ 비동기 로딩 (Asset Loading)
    • ✅ 네트워크 통신
  • 하나의 Process 안에서 여러 Thread를 사용해서 병렬처리가 가능

동기화 (Synchronization)

Mutex

  • 상호 배제 (Mutual Exclusion): 한 번에 하나의 스레드만 접근
  • 문제 상황
    • 하나의 변수, 메모리에서 여러 Thread가 동시에 접근하는 경우
  • 해결 방법
    • mutex를 활용해서 한 Thread가 접근했다면 다른 Thread는 해당 작업동안 접근하지 못하도록 Lock을 걸고 작업이 끝나면 Lock을 해제해서 다른 곳에서 접근할 수 있게 해줌
    • {C++}lock_guard<mutex>를 활용해서 보다 쉽게 해당 Scope에서 lock, unlock을 진행할 수 있음

Semaphore

  • N개의 스레드 동시 접근 허용
  • 게임 활용
    • ✅ 동시 접속자 수 제한
    • ✅ 리소스 풀 관리
    • ✅ 스레드 풀
  • 예제: 리소스 풀 (Resource Pool)

Deadlock 문제란?

  • 교착 상태 : 두 개 이상의 Thread가 서로를 기다리면서 멈춘 상태
  • 발생 조건 (4가지 조건을 모두 만족)
      1. 상호 배제 (Mutual Exclusion)
      1. 점유와 대기 (Hold and Wait)
      1. 비선점 (No Preemption)
      1. 순환 대기 (Circular Wait)
  • Deadlock 발생 예시
    • Thread1과 Thread2에서 각각 Lock을 걸었는데 순서로 인해 서로 해제되지 않아서 교착 상태 발생
  • 해결 방법

Spinlock vs Mutex

  • Mutex
    • 잠금 실패 시 스레드가 Sleep 상태로 전환 (Context Switch 발생).
    • 대기 시간이 길 것으로 예상될 때 사용.
  • Spinlock
    • 잠금 실패 시 루프를 돌며 계속 확인 (Busy Waiting).
    • Context Switch 비용이 없음.
    • 임계 영역(Critical Section)이 매우 짧을 때 유리.

페이징 (Paging)

  • 물리 메모리를 고정 크기 페이지로 분할
  • 특징
    • 페이지 크기: 보통 4KB
    • 외부 단편화 해결
    • 페이지 테이블로 매핑
  • 예제:
    • 가상 주소 → 물리 주소 변환
    • Virtual Address: 0x12345678
    • Page Size: 4KB (0x1000)
Page Number = 0x12345678 / 0x1000 = 0x12345
Offset = 0x12345678 % 0x1000 = 0x678

Page Table[0x12345] → Physical Frame 0x9ABCD
Physical Address = 0x9ABCD * 0x1000 + 0x678 = 0x9ABCD678

가상 메모리 (Virtual Memory)

  • 프로그램이 물리 메모리보다 큰 주소 공간 사용
  • 특징
    • 각 프로세스는 독립적인 가상 주소 공간
    • 실제 필요한 부분만 물리 메모리에 로드
    • 페이지 폴트 (Page Fault) 발생 시 디스크에서 로드
  • 게임 관련
    • 32비트: 4GB 가상 메모리
    • 64비트: 이론상 16EB (실제로는 제한됨)

CPU Cache

  • L1 Cache: 가장 빠름, 작음 (32-64KB)
  • L2 Cache: 중간 (256KB-1MB)
  • L3 Cache: 느림, 큼 (8-32MB)
  • RAM: 가장 느림
  • Cache Line: 보통 64바이트
  • Cache Miss
    • Cold Miss: 처음 접근
    • Capacity Miss: 캐시 용량 부족
    • Conflict Miss: 해시 충돌

vtable의 동작 원리를 설명하시오

vtable(가상 함수 테이블)은 가상 함수를 가진 클래스가 보유하는 함수 포인터 배열입니다. 각 클래스는 하나의 vtable을 가지며, 각 객체는 이 vtable을 가리키는 vptr(가상 포인터)을 가집니다.

가상 함수 호출 시:

  1. 객체의 vptr을 통해 vtable 접근
  2. vtable에서 해당 함수 포인터 가져오기
  3. 함수 호출 (런타임 다형성)

이를 통해 Base* 포인터가 Derived 객체를 가리킬 때도 Derived의 오버라이드된 함수가 호출됩니다.

Deadlock의 발생 조건 4가지와 예방 방법을 설명하시오

발생 조건

  1. 상호 배제: 리소스를 한 번에 하나만 사용
  2. 점유와 대기: 리소스를 가진 채 다른 리소스 대기
  3. 비선점: 강제로 리소스를 빼앗을 수 없음
  4. 순환 대기: 대기 관계가 순환 구조

예방 방법

  1. 순서 강제: 모든 스레드가 같은 순서로 락 획득
  2. try_lock() 사용: 획득 실패 시 포기하고 재시도
  3. 타임아웃 설정: 일정 시간 대기 후 포기
  4. 락 계층 구조: 상위 락 획득 후 하위 락 획득

RAII 패턴의 장점을 설명하시오

RAII(Resource Acquisition Is Initialization)는 리소스 획득을 객체 초기화와 동시에 하고, 객체 소멸 시 자동으로 리소스를 해제하는 패턴입니다.

장점

  1. 예외 안전성: 예외 발생 시에도 자동 정리
  2. 메모리 누수 방지: 스코프 벗어나면 자동 해제
  3. 코드 간결성: 명시적인 cleanup 코드 불필요
  4. 유지보수성: 리소스 관리 로직이 캡슐화됨
  • 예: unique_ptr, lock_guard, fstream 등
